# 窄宽自适应规则（AI 会话面板打开后尤其重要）

> 版本：0.1.5 起执行。起因：AI 面板打开后业务区只剩 60%–75% 宽，看板「最近 KPS / MRI / 激素」
> 被压成一列列竖排单字，营养页「语境一 · 激素期：」同病。用户对照宫颈癌工作台指出这里不如它。
> 规则不是"多加几个断点"，而是**别让卡内元素横向互挤**。

## 0. 先记住一件事：业务区视口 = 业务面板宽度

宿主用 customFrame 时，业务界面跑在 iframe 里，AI 面板一展开 iframe 就变窄。
所以 `@media (max-width: …)` 量到的**就是业务区宽度**，不是窗口宽度：

- 不要用 `window.innerWidth` 判断"要不要换布局"（那是整个窗口，业务区可能只有它的 65%）；
- 断点值直接按"业务区能放下什么"来定，不要按设备类型（desktop/tablet）来想。

## 1. 硬规则（每条都有探针或单测兜底）

| # | 规则 | 违规表现 | 兜底 |
| --- | --- | --- | --- |
| 1 | **卡内"标签 + 值 + 说明"必须纵向堆**，不许并排 | 三行文字各挤成一列竖排单字 | `test/responsive.test.mjs` |
| 2 | 多块并排用 **grid + `minmax(0,1fr)`**，不要 `flex:1` | 块宽由内容牵动，窄宽下先后失守 | 同上 |
| 3 | 行内标签（`<b>语境一：</b>`）**不能成为 flex item** | 标签被压到 30px，逐字换行 | 同上（`::before` 绝对定位替代 flex 圆点） |
| 4 | 允许收缩的容器都要 `min-width:0` | 撑破父容器、出现横向滚动条 | `probe:resp` |
| 5 | 长路径 / 表格横向滚动是**有意为之**，但要给 `.scroll-hint` | 读者不知道右边还有内容 | 人工 |
| 6 | 数字与日期不换行（`white-space:nowrap` 只在短 token 上） | `2026-09-25` 被拆成两行 | 人工 |

## 2. 断点取值（照现有实体，别再发明第四档）

| 宽度 | 变化 | 理由 |
| --- | --- | --- |
| ≤ 1180 | 看板三块「最近变化」降为 **2 列**，按钮独占一行；`.dash-cols` 单列 | 3 列时每块只剩 200px 出头，注释行必挤 |
| ≤ 900 | 三块降为 **1 列**；侧栏转横向导航；AI 面板转覆盖抽屉 | 再并排就只剩 100px 级 |
| ≤ 600 | 顶部版本 chip 隐藏、表格内边距收紧 | 手机窄屏 |

> 结论：**任何"每块宽度 < 220px"的多列布局都算设计错误**，先降列数再考虑缩字。

## 3. 怎么验（不要口头说"没问题"）

```bash
npm run probe:resp        # 真实 Chrome，8 档宽度 × 10 个一级页，出数字
```

扫描规则（`scripts/probe-responsive.mjs`）：

- **竖排单字**：元素宽度 < 3em 且自身文字 ≥ 6 字 → 一行只放得下 1–2 字，必是挤压；
- **横向溢出**：`documentElement.scrollWidth > innerWidth + 1`；
- **内容被裁**：容器 `overflow:hidden|clip` 且 `scrollWidth > clientWidth + 2`（有文字才算；
  `overflow:visible` 的溢出是装饰，不算）。

退出码非 0 即视为不通过。改完样式先跑它，再看 `docs/shots/dev/responsive-940-dash.png`。

## 4. 家族复用提示

小粉宝 / 小莲宝 / 小铃铛等若也有"标签+值+注 横排"的摘要条或 flex 包行内标签，
装机会出现同样的竖排单字。把 `scripts/probe-responsive.mjs` 的 `SCAN` 段整段抄过去即可，
只需把 `#main` 与页面 hash 换成各自的选择器。
