### 定义

甲状腺癌是起源于甲状腺的恶性肿瘤，按病理分成四类：乳头状癌、滤泡状癌（两者合称分化型，DTC）、髓样癌（MTC，起源于滤泡旁 C 细胞）、未分化癌（ATC）。卫健委《甲状腺癌诊疗指南（2022 年版）》记载，患者最先接触的往往是一份超声报告的结节分类，而不是「癌」这个字。

结节分类有两套体系并存：卫健委指南的 TI-RADS（0/1/2/3/4a/4b/4c/5/6）与中华医学会 7 学会的 C-TIRADS（1～6 类）；2022 版原文写「目前 TI-RADS 分类并未统一，可参考表 1 标准」，即不强制某一体系。穿刺结果按 Bethesda（TBSRTC）6 级报告，每一级对应一段恶性风险区间——区间是统计口径，不是对某一颗结节的判定。分期按 AJCC 第 8 版：分化型（乳头状 / 滤泡状）以 55 岁划线，小于 55 岁只有 Ⅰ 期（无远处转移）与 Ⅱ 期（有远处转移）；髓样癌与未分化癌不按年龄分层，各用自己的分期表（卫健委 2022 版表 5 / 表 6，p25–p28），不能拿分化型的 Ⅰ～ⅣB 去套。微小乳头状癌也不等于「低风险」：指南原文写 ≤1cm 微小癌「复发风险也很低。但微小癌并不都是复发风险低的肿瘤」，约 20% 多灶性微小癌出现颈淋巴结转移。本台不判断结节良恶性，判读归超声科、病理科与外科。

### 目前治疗全景概要

只列指南与说明书里出现过的手段类别，按病期与线序分组，不排序、不比优劣。

**早期 · 分化型（DTC）**：主动监测——低危微小乳头状癌可以不开刀、每 6 个月重新评估（2022 版 p32–p33 明确列出这条路径）；手术——腺叶切除或全切，选择取决于肿瘤大小、对侧叶情况、淋巴结与患者意愿，颈部淋巴结清扫按治疗性或预防性分别记录；术后风险分层——ATA 初始复发风险分低、中、危三层（2022 版 p40–p42 转述 2015 ATA 定义），分层结果决定后面用不用碘、TSH 压到多少。

**术后 · 辅助与抑制**：碘-131 分三种用途——清甲（清除术后残留的正常甲状腺组织）、辅助（处理镜下残留或高危因素）、清灶（治疗摄碘的转移灶）；适应证口径为高危列入推荐、中危可考虑、低危不推荐（2022 版 p42）。禁忌：妊娠或哺乳期、计划 6 个月内妊娠者。TSH 抑制——用左甲状腺素把 TSH 压到目标区间，目标随风险与治疗反应变化（高危初始低于 0.1、中危 0.1～0.5、低危 0.5～2.0；2022 版 p43–p44），目标值一律由医生给出，本台不按公式生成。

**复发与远处转移**：2022 版 p63 列出的路径顺序是手术（可能治愈者）、¹³¹I（病灶摄碘者）、外放疗、TSH 抑制下观察（无进展或进展慢、无症状）、化疗与靶向药物及临床试验。「Tg 阳性、扫描阴性」——全清后 Tg 持续高于 10 ng/ml 而影像未见病灶，可经验性碘治疗后复评；扫描仍阴性则归入碘难治性 DTC，终止碘治疗（p45、p64）。碘难治性 DTC 的靶向药只列存在该获批路径：索拉非尼（2017-03）、仑伐替尼（2020，批件号待核验）、安罗替尼（2021-01 与 2022-04 两处记录有出入，待核验）、多纳非尼（2022-08-12，待核验）；塞普替尼 2022-09-30 NMPA 附条件批准（RET 融合甲状腺癌、RET 突变型 MTC）。

**髓样癌与未分化癌**：MTC 手术范围更广（全切加颈清），术后不需要 TSH 抑制，随访以降钙素、CEA 与超声为主（p64），部分为遗传性、需查 RET 胚系突变；ATC 就诊时多已局部晚期，治疗以综合治疗为主——放疗（指南提到 60Gy 语境）± 手术 ± 化疗或靶向（p32、p47）；BRAF V600E 突变的 ATC 用达拉非尼联合曲美替尼获 FDA 批准（2018-05），尚未在中国获批该适应症，本台按「检测存在、境外获批、境内未获批」三层呈现。

> 以上是文献与指南里列出的手段，按病期与线序排列，不代表任何一项适合你。选哪一个，这一句需要问你的医生。

## 开发与本地验收

需要 Node.js 22+、Git、包管理器和可用 DSH Desktop；采用 SQLite 时另核验 node:sqlite 版本条件。宿主 peers 的范围仅是模板基线，请与目标 Desktop 实际依赖核对。

```bash
npm install
npm run check
npm run pack:check
npm pack
```

`npm run check` 只保证"能装"（语法 + 装包合同），第一天就该是绿的。`npm run audit` 管"还是不是家族里的一员"：版本三处一致、`lib/layout.js` 面板参数单一来源、检查链完整、文档与密钥卫生，**只看代码与文件，不看文档自述**。新项目刚生成时 audit 必然有 fail，那是待办清单；交付/发布前必须清零，存在 fail 不得发布（`npm run release:check` 一次跑完两者）。

跑的时间点：**每次改完**跑 `check`；**G2 原型确认后、写业务代码前**先跑一次 `audit`（这时缺的多是 `lib/layout.js`、`VERSION` 这类结构，越早补越便宜）；**交付/装机前**必须跑 `release:check`；**发布或投稿前**把 `npm run audit --json` 的 `xx/xx 通过 · N 失败 · M 待人工` 抄进 `docs/RELEASE.md` 的「家族一致性」一行。`✗` 是结构缺口（补齐，或在 `docs/DEV-REQUIREMENTS-<日期>.md` 写明偏离理由并由用户确认），`!` 是需人工判断的项（逐条给「已人工确认 / 确实没有」）。

`npm install` 可能按 npm 策略解析 peer；勿为消警告重复打包宿主 runtime。客户端本身是单文件；引入 TS/组件库后需添加构建步骤并保留单文件导出。

本地安装入口以当前 Desktop/CLI 帮助为准。安装后按 [docs/06-VALIDATION-AND-RELEASE.md](docs/06-VALIDATION-AND-RELEASE.md) 与官方自测完成真实 UI 验收，并填写 [docs/ACCEPTANCE.md](docs/ACCEPTANCE.md)。静态检查不代表已加载。

Logo 来源与使用限制见 assets/README.md。许可证、作者、仓库/发布策略由本项目维护者确认后填写；模板默认为 private/UNLICENSED。
